# Agent execution review — 2026-10-25

## Scope

Reviewed the path from web/Telegram input through durable chat jobs, clarification routing, provider calls, skill loading, bounded memory/history/tool context, guarded operations, scheduled reports and notification delivery. Existing OAuth/session/CSRF checks, request hashes, optimistic resource versions, unknown-write handling and approval boundaries remain in place.

No live calendar mutation, test Telegram notification, paid provider, GitHub Actions run or provider-login bypass was needed for verification. Model-facing regression tests use local stubs; PostgreSQL behavior uses an isolated embedded PostgreSQL engine. This review is targeted engineering verification, not a guarantee that a probabilistic model or every upstream service can never fail.

## Findings addressed

| Finding                                                                               | Change                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Timezone-only preferences defaulted the saved language to English                     | Language is optional in the operation; updates preserve the old value and fresh installations default to English.                                                                                                                                                               |
| A pending clarification was injected into any later request with the same skill group | Only an explicit recognized continuation receives the authoritative clarification block. Ordinary new requests keep normal chronological history without inheriting the old task.                                                                                               |
| Completed tasks entered daily/weekly briefings and could crowd out open tasks         | Task-state filtering runs in the repository before pagination, in both PostgreSQL and the demo store. Model memory reads and the memory API can request open/done tasks.                                                                                                        |
| Full tool results could overflow transport limits, especially with multibyte text     | Whole-record byte budgets, explicit partial-result markers, bounded routine/reminder context and adaptive history allocation leave transport headroom. Missing records are unknown, not absent.                                                                                 |
| A truncated initial routine list had no targeted lookup                               | Added read-only routine name/ID lookup. Updates must reference a version actually provided in initial bounded context or current reads.                                                                                                                                         |
| The read loop could perform one last external read without any budget left to answer  | Allow at most three tool-read rounds followed by an answer; reject a further read before executing it. The overall model deadline remains eight minutes.                                                                                                                        |
| A completed or orphaned durable request could be picked up as fresh work              | Terminal request states are reconciled without generation; missing request state fails the job visibly rather than leaving it running. Existing operation idempotency still prevents repeated writes after uncertain outcomes.                                                  |
| Telegram command failures lost the originating chat context                           | Error delivery stays scoped to the originating allowed chat; unverified destinations do not get a fallback send.                                                                                                                                                                |
| Turkish no-save matching also matched positive “kaydetmeni” requests                  | Word-aware negative intent matching distinguishes explicit save requests and recognizes common English and other no-save wording. Model instructions remain necessary beyond this small vocabulary.                                                                             |
| Connection credentials embedded in retrieved content could reach generation           | Recognized credential patterns are redacted recursively in model-facing serialized data. Source records are unchanged. Credential-bearing response envelopes are rejected before actions/storage/delivery. This is pattern-based minimization, not a universal secret detector. |
| Repeated instruction file reads and independent memory reads added overhead           | Bootstrap/selected skill content is reused within a request and independent memory/profile lookups run together. Reviewed file changes still alter provider conversation revisions on the next request.                                                                         |
| A misrouted conversation could claim a completed write without a tool                 | The existing bounded contract correction also covers ungrounded completion claims from read-only/conversation routing; no operation is invented. This is a heuristic guard, with server execution evidence remaining authoritative.                                             |
| Saved assistant language was restricted to two values                                 | Validated BCP 47 preferences, an extensible language input, deterministic multilingual receipts and automatic message text direction. See LANGUAGES.md for coverage limits.                                                                                                     |

The execution protocol revision changes native provider continuation keys once on upgrade so older unsanitized tool context is not resumed. The durable archive and indexed recall remain independent of provider sessions. Native providers may maintain their own remote history; application input budgets do not claim to control or erase that remote storage. No general shell execution, automatic policy rewriting, new background model calls or hosted infrastructure was added.
